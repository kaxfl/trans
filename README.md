# 划词翻译

> 一个为 **代码阅读者** 和 **游戏模组开发者** 做的 Windows 划词翻译工具。
> 本地运行、离线可用、零调用成本。

---

## 它解决什么问题

读英文代码、英文文档、游戏模组脚本时，最烦的不是"看不懂"，
而是 **切屏 → 忘了 → 切回来 → 再查一遍** 这个循环。

这个工具把翻译压缩成一步：**选中文字，译文就在鼠标旁边出现。**

---

## 功能

### 1. 划词翻译（核心）

在**任意软件**里双击一个单词、或拖拽选中一段，译文弹窗就会出现。

- 支持浏览器、VSCode、IDEA、QQ、PDF 阅读器、游戏客户端……
- 不依赖目标软件是否支持无障碍接口（全局鼠标钩子 + 剪贴板取词）
- **鼠标移开选区 → 弹窗立刻消失**；移回来 → 再翻一次
- 点空白处 / 滚轮滚动 → 弹窗收起

| 快捷键 | 作用 |
|---|---|
| `Ctrl + Alt + .` | 翻译当前选区 |
| `Ctrl + Alt + Z` | 切换「划词翻译」总开关 |
| `Ctrl + Alt + ,` | 切换「选中自动弹窗」（关掉后只在按键时才翻） |
| `Alt + Enter` | 唤出主窗口 |

> 左右 Alt/Shift 在系统层是同一个修饰键，无法单独注册，所以只用侧重点一致的三键组合。

### 2. 三种展示形态

| 形态 | 触发 | 显示 |
|---|---|---|
| **词典** | 选中一个英文单词 | 音标 + 柯林斯星级 + 词性 + 多条释义 |
| **代码模式** | 选中标识符（`lastUpdateTime`） | 按 `snake_case` / `camelCase` 拆词，逐词给出含义 |
| **普通翻译** | 句子 / 段落 | 通顺译文 |

**代码模式**是这个工具和普通翻译软件最大的区别：
选中 `BUYOUT_SECRET` 时，它不会把整个词硬翻成一个怪词，
而是拆成 `BUYOUT → 买断` / `SECRET → 密钥`。

### 3. 代码块兜底（原格式保留）

模型经常对代码块直接说"翻不了"。这时自动降级为**逐词查词典**：

```text
输入：has_completed_focus = JAP_advance_one_hundred_million_fireballs
输出：has_完整的_焦点 = JAP_前进_一(个)_百...
```

- **符号、缩进、换行一个字符都不动**——因为只有连续字母会进入翻译流程
- 词典里查不到的词保持原文（不编造）
- 词形说明（"have的第三人称单数"）、词性前缀（`n.` `prep.`）都会被过滤掉

### 4. 四个翻译源

| 引擎 | 需要什么 | 特点 |
|---|---|---|
| 本地词典 | 无（内置 35 MB） | 单词查询 **26 微秒**、离线 |
| 本地模型 | Ollama + 显存 | 句子翻译 0.5 秒、完全离线 |
| **DeepSeek 云端** | 一个 API Key | 质量最高、按量计费（短句约 0.0003 元）|
| MyMemory | 联网 | 免费兜底，质量一般 |

本地模型没起来时会**自动拉起 Ollama**；都不可用时按顺序回退，不会白屏。

### 5. 本地词典（56 万个单词，35 MB）

内置 ECDICT 精简版，**查单词不经过任何模型**：

- **12–254 微秒**返回（对比调模型 1–3 秒）
- 词性准确（模型会把 `among` 标成名词/动词，词典不会）
- 不需要联网、不需要 Ollama、不占显存

### 6. 深色 / 浅色主题

设置里可选「跟随系统 / 深色 / 浅色」，**主窗口和浮窗同时生效**，切换不闪烁。

### 7. 本地缓存

- 同一个词查第二次瞬间返回，显示"查过 N 次"
- 逐词兜底的结果**不写缓存**（纯查表，缓存反而会挡住算法改进）

### 8. 隐私

- 默认**关闭**"复制即译"，避免复制密码时被外发
- 可以随时暂停剪贴板监听
- 本地模型模式下，内容**不出本机**

## 安装

### 方式一：安装包（推荐）

下载 `划词翻译_x.y.z_x64-setup.exe`，双击安装（会自动创建桌面快捷方式）。

安装包**已内置本地词典**，装完就能离线查单词。

### 方式二：免安装

解压后直接运行 `划词翻译.exe`。

## 配置本地模型（可选，但强烈建议）

**不配也能用**（会自动回退到免费的 MyMemory 云端接口），
但配上之后**快得多、且完全离线**。

### 步骤

1. 安装 [Ollama](https://ollama.com/download)
2. 拉取模型：

```powershell
ollama pull qwen3:1.7b
```

3. 确认服务在跑：

```powershell
Get-NetTCPConnection -LocalPort 11434 -State Listen
```

4. 打开本软件 → 设置 → 本地模型 → 点「测试连接」→ 选择模型 → 「用这个模型」

### 模型选择建议

| 模型 | 体积 | 显存 | 速度 | 质量 |
|---|---|---|---|---|
| `qwen3:0.6b` | 0.49 GB | ~1 GB | 最快 | 短词不稳 |
| **`qwen3:1.7b`** | **1.27 GB** | **~2 GB** | 快 | **推荐** |
| `qwen3:4b` | ~2.5 GB | ~3.5 GB | 中 | 更好 |

实测环境：RTX 4050 Laptop（6 GB 显存），1.7B 全量跑 GPU，句子翻译 0.5–1 秒。

> 想更省资源：让 Ollama 只在翻句子时才启动——查单词完全不需要它。

## 技术实现

| 层 | 技术 |
|---|---|
| 外壳 | Tauri 2（Rust + WebView2） |
| 前端 | 原生 HTML/CSS/JS（无框架） |
| 取词 | 全局低级鼠标钩子（`WH_MOUSE_LL`）+ 合成 Ctrl+C + 剪贴板还原 |
| 选区读取 | Windows UIA（`IUIAutomation`），与剪贴板路径互为兜底 |
| OCR | WinRT `OcrEngine` + GDI 截屏 |
| 翻译 | OpenAI 兼容接口（Ollama / llama.cpp / LM Studio 通用） |
| 词典 | ECDICT → 自定义二进制格式（mmap + 二分查找） |

### 几个踩过的坑（也是这个项目的技术要点）

1. **不能只靠 UIA 取词**。Chrome、VSCode、IDEA 默认不暴露 `TextPattern`，
   QQ、游戏、自绘界面则永远不暴露。所以必须准备"钩子 + 剪贴板"这条兜底路径。
2. **UIA 在高 DPI 下字符偏移会错位**。同一个词能读出 `immune` / `mmune` / `mmune t`
   三个版本。解法：进程声明 Per-Monitor V2 DPI 感知 + 用选区矩形做合理性校验。
3. **低级鼠标钩子回调里不能做重活**。UIA 读取是跨进程 COM 调用，几十毫秒起步，
   放在钩子里会拖慢整个系统的鼠标输入。解法：钩子只做微秒级判定，活丢给工作线程。
4. **不要维护"另一个组件才知道真相"的影子状态**。
   弹窗会被前端定时器自己关掉，后台却以为它开着——这类 bug 极难排查。
   解法：隐藏窗口是幂等操作，直接调，别判状态。
5. **合成 Ctrl+C 会触发自己的剪贴板监听**，导致弹窗"闪一下"。
   解法：内部复制期间加计数守卫 + 文本指纹。
6. **Ollama 的 OpenAI 兼容端点不认 `think: false`**。
   同一个翻译请求：

   | 端点 | 耗时 | 生成 token |
   |---|---|---|
   | `/v1/chat/completions` + `think:false` | 3805 ms | 186 |
   | `/api/chat` + `think:false` | **187 ms** | **3** |

   兼容层照样生成整条思维链，只是把它塞进 `message.reasoning`（正文看着正常，
   时间全花在"思考"上）。所以本程序**优先走 Ollama 原生 `/api/chat`**，
   失败才退回 `/v1`——后者用于兼容 llama.cpp / LM Studio / vLLM。
   **20 倍差距，全在一个端点选择上。**

## 已知限制

- **仅 Windows**（重度依赖 Win32 API）
- 部分软件会拦截合成按键，取词失败时请用 `Alt + .` 或框选 OCR
- 以管理员身份运行的窗口，需要本程序也以管理员运行才能取词
- ECDICT 对较新的编程词汇（如 `refactor`）覆盖不全，这类词在逐词兜底时会保持英文原文
